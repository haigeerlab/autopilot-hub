## 1. 目标

一个仓库从零开启自动化，半小时内、不填表（方向文档成功标准）。体检是第一步：一条命令，告诉你缺了什么、缺了会怎样、要不要帮你补，并说清现在能开到哪一档。

## 2. 命令

```bash
python3 -B <autopilot-hub>/checkup/cli.py --repo <本地检出> [--base main] [--run-check] [--out <目录>] [--json]
```

- 默认输出给人看的中文报告；`--json` 输出机器可读结果（给编排和 spec-guard 的预览用）。
- `--out` 指定补丁和命令写到哪个目录；不给时只在报告里列出、不写文件。
- 退出码：0 体检完成（不论有多少提醒）；2 参数或仓库读不了；3 环境不就绪（`gh` 没登录、网络不通）。**不会因为"缺东西"而返回失败**。

## 3. 检查清单（第一版）

| # | 项 | 怎么判 | 范围 | 缺了会怎样（报告里的大白话） | 能帮你补 |
| --- | --- | --- | --- | --- | --- |
| C1 | 有能跑的检查命令 | 读 `interface.yml` 里登记的 `check`；没有就从会被 PR 触发的 workflow 里找第一条像测试或构建的步骤 | 仓库 | 没有它，**不能开自动合并**（硬卡） | 不能（要你说用哪条） |
| C2 | 检查真的能跑（`--run-check`） | 临时克隆里跑 C1 的命令，看退出码，留末尾输出 | 仓库 | 命令写了但跑不起来，自动合并的证据就是假的 | 不能 |
| C3 | 分支保护生效 | 规则集与旧版保护合并看：禁止强推、禁止删除、只能经 PR | 仓库 | 有人或 AI 能绕过检查直接改 main | ① 规则集补丁 |
| C4 | 主干 CI 是绿的 | main 上最近一次已完成的推送或定时运行 | 仓库 | 在本来就红的基线上开 PR，失败说不清是谁的 | 不能 |
| C5 | PR 会跑检查 | workflow 在 `pull_request` 上触发并调用了 C1 的命令 | 仓库 | 只在本机跑过，CI 上没人复核 | 不能（第二批生成） |
| C6 | 密钥扫描与推送保护 | 仓库安全设置 | 仓库 | AI 提交时可能把密钥带进仓库 | 只给开启步骤 |
| C7 | workflow 默认权限只读 | 仓库 Actions 设置 | 仓库 | 外部 PR 借 workflow 拿到写权限 | 只给开启步骤 |
| C8 | action 固定到 40 位提交 | 只看本次改过的 workflow 文件 | 增量 | 第三方 action 被篡改时 CI 跟着变 | 不能（列出要改的行） |
| C9 | 没有危险触发写法 | 只看本次改过的 workflow：`pull_request_target`／`workflow_run` 又检出或执行 PR 代码 | 增量 | 外部 PR 拿到高权限执行代码 | 不能（列出位置） |
| C10 | 依赖按锁文件装 | 只看本次改过的依赖清单：有对应锁文件，CI 用锁定安装 | 增量 | 同一提交两次装出不同依赖，检查结论不可信 | 不能（列出命令） |
| C11 | 风险分级配置 | 有没有 `.github/autopr/risk-tiers.json` | 仓库 | 没有时按通用规则，很多路径会被当成 T3 | ② 一行配置 |

**报告结尾给一句结论**：现在能开到哪一档（不接管／只接管 Plan／接管到合并），差哪一项。"只接管 Plan"不依赖以上任何一项，永远可开。

## 5. 验收标准

1. 单元测试覆盖 C1–C12 每一项"有"和"没有"两种情况；GitHub 返回用夹具；`--run-check` 用一个临时小仓库。
2. 本机对 agent-relay、autopilot-hub、tab-leader 各跑一次，报告你抽看：提醒是不是大白话、有没有误报。
3. 三样补丁各生成一次：规则集 JSON 能通过 `gh api` 的格式校验（只做 `--method GET` 对照，不执行写入）、`risk-tiers.json` 能被切片 4 读、例外说明草稿语句通顺。
4. 半小时目标：从跑体检到看懂报告、决定补哪几项，你实测一次计时。
